候选 ID 是什么：279 个文件逐一计算 sha256 后形成清单，候选 ID 是这份清单本身的 sha256。评审和验收都在开始与结束时校验它，保证两者检查的是同一份代码。

已知限制（均经独立评审同意放行）

  • I-07 读者被停用后，已登录的会话仍能访问部分接口（包括修改本人口令），且会话持续活动时不会因 30 分钟空闲超时而失效；该读者无法重新登录，管理员也无法再为其借书或续借。
  • I-04 表单错误处理工具在 3 个功能模块中各有一份重复代码。
  • I-06 前端主包约 898 KB，构建时有体积告警（不是错误）。
  • R-01 登出时若有旧请求仍在途、且在重新登录后才返回“未登录”响应，可能把新会话登出（安全方向，不泄露数据）。

1 · 完成了什么

按角色的功能

角色菜单与功能
管理员仪表盘；图书检索；图书管理（新建、编辑、副本追加、改状态、删除）；分类管理；读者管理（新建读者同时创建账号、停用/启用、删除、重置口令）；流通柜台（借书、还书、续借，回车提交）；借阅记录（过滤、分页）；逾期报表；借阅统计（日/月粒度、热门图书）；修改口令
读者图书检索与详情（只显示可借数量，不显示条码）；我的借阅（当前/历史，逾期标红，无续借按钮）；我的资料；修改口令

业务规则（用户决定 D1–D7）

  • D1：每位读者同时在借上限 5 本；借期 30 天；可续借 1 次，从当前应还日顺延 30 天。
  • D2：只有管理员能续借。
  • D3：Spring Boot 4.1.x。
  • D4：纳入“修改本人口令”；同一读者不能同时借同一书目的两个副本；ISBN 严格校验位检查。
  • D5：后端 18095、前端 15195（E2E 用 18096 / 15196）；时区 Asia/Shanghai。
  • D6：允许下载方案内依赖；新增依赖需用户批准。
  • D7：需求中的“rreact”即 React；技术栈为 Spring Boot + React + SQLite。
  • 非目标：预约、罚款、部署上线。

系统结构

数据模型

app_user 1—1 reader（读者档案）；category 0..1—N book（图书可不归属分类）；book 1—N book_copy（副本，带条码与状态）；reader 1—N loan；book_copy 1—N loan（同一副本同时最多 1 条在借，由部分唯一索引保证）。

技术栈

后端Spring Boot 4.1.2、JDK 21、Spring Security、Hibernate 7.4.13（社区 SQLite 方言）、Flyway 12.4.0、sqlite-jdbc 3.53.4.0、JUnit 5
前端React 19.3、React Router 7.18、antd 6.7、TanStack Query 5.108、Vite 7.3、TypeScript 5.9、Vitest 5.1、Playwright 1.65

演示数据

5 个分类、12 本书、24 个副本、3 个演示读者（reader3 已停用）、10 条借阅（1 条在借、1 条逾期、8 条已还）。

4 · 遗留风险与建议
编号内容影响建议优先级
R-01登出时若有旧请求在途、在重新登录后才返回 401，会把新会话登出偶发体验问题，安全方向，无数据泄露请求带“会话代际”标记，迟到的旧代际响应直接忽略中
I-07停用读者的已登录会话在空闲超时前仍能访问部分接口（包括修改本人口令）无法借书、续借或重新登录；会话持续活动时不会因空闲超时而失效每个请求复查账号状态，或停用时注销会话中
I-04表单错误处理工具在 3 个模块中重复维护成本合并到共享层低
I-06前端主包约 898 KB首屏加载稍慢（本机使用影响小）按需拆分 antd 等大依赖低
R-04追溯矩阵中个别用例计数有偏差；README 写“两份”重复代码实际三份描述不精确，不影响证据有效性下一次改动时一并修正低

任何代码或文档改动都会产生新的候选：需要重新生成快照，并对受影响范围重新评审和验收。
